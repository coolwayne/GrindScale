# GrindScale v0.1 MVP Design

## 1. Product Goal

Build a mobile app that analyzes coffee grounds from a photo and reports grind uniformity in a way users can act on.

Primary value for MVP:
- Stable and repeatable "relative uniformity" analysis.
- Clear visual feedback and brewing-oriented suggestions.

Out of scope for v0.1:
- Full 3D volume reconstruction.
- Grinder fingerprint library.
- Multi-device calibration profiles.

## 2. Target Users

- Home brewers with V60, AeroPress, moka pot.
- Baristas doing quick QA checks between grinder setting changes.

## 3. MVP Success Criteria

- Analysis completes in <= 1.5s per image on target phone.
- Repeated capture variance for same sample: CV drift <= 10%.
- Particle detection recall >= 85% on labeled internal test set.
- Users can correctly interpret result and suggestion in usability testing.

## 4. User Journey

1) User opens app and chooses brewing method (default: V60).
2) App shows capture guide overlay:
   - Spread grounds on white paper.
   - Avoid direct sunlight.
   - Keep camera within suggested distance.
   - Optionally place a reference coin.
3) User captures image.
4) On-device pipeline runs and detects particles.
5) App displays:
   - Histogram
   - Uniformity score (0-100)
   - Fine/target/coarse ratio
   - Color overlay (blue/green/red)
   - One-line brewing suggestion

## 5. Functional Requirements

### 5.1 Capture Guidance

- Live camera preview with circular ROI.
- Quality checks before shutter:
  - Blur score threshold (Laplacian variance).
  - Over/under-exposure threshold.
  - ROI occupancy threshold (enough grounds in frame).
- Prompt user to retake if quality fails.

### 5.2 Particle Analysis

- Detect individual particles in ROI.
- Handle touching particles with watershed split.
- Filter obvious noise by min/max area.
- Compute per-particle features:
  - Area
  - Equivalent diameter
  - Major/minor axis
  - Circularity

### 5.3 Statistics and Scoring

- Core metrics:
  - Mean diameter
  - Standard deviation
  - Coefficient of variation (CV)
  - D10/D50/D90
- Buckets:
  - Fine / Target / Coarse based on brewing profile.
- Uniformity score:
  - 100 - weighted penalty(CV, out-of-target ratio, bimodality)

### 5.4 Reference Object Calibration (Optional in Capture)

- Support initial coin set:
  - TWD 10
  - USD quarter
- If detected:
  - Convert px to um.
- If not detected:
  - Keep relative-pixel mode and show "relative analysis" badge.

### 5.5 Result Presentation

- Histogram with target range highlighted.
- Color overlay on source image:
  - Blue: fine
  - Green: target
  - Red: coarse
- Text recommendation generated by simple rule engine.

## 6. Non-functional Requirements

- On-device processing only for MVP (no cloud dependency).
- Median memory use under acceptable mobile limits.
- No photo upload by default (privacy-first).
- Basic crash logging and performance telemetry.

## 7. Technical Architecture

## 7.1 Client Modules

- `CaptureModule`
  - Camera control, guide overlay, quality checks.
- `ImagePipelineModule`
  - Preprocess, segmentation, watershed, contour extraction.
- `MeasurementModule`
  - Feature extraction and size conversion.
- `ScoringModule`
  - Stats, score, brewing profile comparison.
- `VisualizationModule`
  - Histogram + overlay rendering.
- `RecommendationModule`
  - Rule-based recommendation text.
- `StorageModule`
  - Local history snapshots and settings.

## 7.2 Data Flow

1) Camera frame -> quality checks.
2) Accepted frame -> ROI crop.
3) Preprocess -> binary mask.
4) Segmentation -> labeled particles.
5) Features -> statistics.
6) Statistics + profile -> score and recommendation.
7) Persist result summary locally.

## 8. Computer Vision Pipeline Spec (v0.1)

1) Convert ROI to grayscale.
2) Apply Gaussian blur (kernel 5x5 as baseline).
3) Adaptive threshold (Gaussian, inverse binary).
4) Morphology:
   - Opening to remove speckles.
   - Closing to fill small holes.
5) Distance transform + local maxima.
6) Watershed split for touching components.
7) Extract contours and filter by area bounds.
8) Compute equivalent diameter:
   - `d_eq = 2 * sqrt(area / pi)`

Fallback if watershed fails on noisy sample:
- Use contour-only mode and raise confidence warning.

## 9. Brew Profile Model (Initial)

Define target bands as normalized ratio around profile median.

Example starter profiles:
- `V60`: narrower target band, lower tolerated fines.
- `Moka`: wider band, higher tolerated fines.
- `FrenchPress`: coarser center with fewer fines.

Profile object:
- `name`
- `target_d50_um`
- `target_band_um_low`
- `target_band_um_high`
- `fine_threshold_um`
- `coarse_threshold_um`
- `weight_cv`
- `weight_outlier`
- `weight_bimodal`

## 10. Recommendation Rules (MVP Rule Engine)

Inputs:
- Fine ratio
- Coarse ratio
- CV
- Bimodal flag

Example rules:
- High fines + high CV:
  - "Fine ratio is high. For pourover, reduce agitation or go 1 click coarser."
- High coarse ratio:
  - "Particle spread leans coarse. Consider 1 click finer for better extraction."
- Bimodal:
  - "Distribution appears bimodal. Grinder alignment or burr condition may need check."

## 11. Data Model (Local)

- `id`

- `brew_profile`
- `mode` (relative | calibrated)
- `pixel_to_um` (nullable)
- `particle_count`
- `mean_diameter`
- `std_diameter`
- `cv`
- `d10`
- `d50`
- `d90`
- `fine_ratio`
- `target_ratio`
- `coarse_ratio`
- `uniformity_score`
- `bimodal_flag`
- `recommendation_text`
- `processing_time_ms`

## 12. API Boundaries (Internal Interfaces)

`analyze(image, config) -> AnalysisResult`
- input:
  - image
  - ROI
  - calibration info
  - brew profile
- output:
  - metrics
  - per-particle labels for overlay
  - recommendation payload

`checkCaptureQuality(frame) -> QualityReport`
- blur score
- exposure score
- occupancy score
- pass/fail + reason

## 13. QA and Validation Plan

- Build labeled dataset:
  - 200-300 images across lighting conditions and grind settings.
- Compare auto-detection to manual annotation:
  - count accuracy
  - diameter distribution drift
- Repeatability test:
  - same sample, multiple shots.
- Device test:
  - at least 2 phone models.

## 14. 6-Week Delivery Plan

Week 1:
- Camera UI + capture guide + quality checks.

Week 2:
- Basic CV pipeline without watershed.

Week 3:
- Watershed + contour feature extraction.

Week 4:
- Statistics, scoring, histogram, overlay.

Week 5:
- Coin calibration and dual-mode result flow.

Week 6:
- QA pass, threshold tuning, stability optimization.

## 15. Risks and Mitigations

- Lighting variance risk:
  - Mitigate with stronger capture constraints and adaptive threshold.
- Particle overlap risk:
  - Mitigate with watershed and confidence indicator.
- False trust in absolute size:
  - Always display mode badge (relative vs calibrated).
- Device camera differences:
  - Add per-device tested profile list and conservative defaults.
